# Полный аудит и дорожная карта

Аудит ведётся по этапам: изменение не принимается, пока независимый проверяющий не повторит тесты и не проверит diff. Тестовые файлы пользователя остаются только в папке `Тест`, которая исключена из Git.

## Закрытые риски

| Приоритет | Проблема | Статус | Этап |
|---|---|---|---|
| P1 | Уязвимая версия PDF.js | Обновлена; `npm audit --omit=dev` возвращает 0 уязвимостей | 1 |
| P1 | Бесконечная загрузка, лимиты и неочищаемые временные импорты | Ограничения, token, TTL, удаление прежнего импорта и обработка ошибок | 1, 4 |
| P1 | Некорректное оглавление и пустые листы | Модель блоков, отсечение напечатанного содержания, сохранение разметки, тесты на большой DOCX | 2, 3 |
| P1 | Одна страница содержала только заголовок | Заголовок удерживается со следующим текстом; есть регрессия | 3 |
| P1 | Новая книга открывалась на странице предыдущей | Сброс на страницу 1 при новом импорте; позиция сохраняется только при resize | 4 |
| P1 | Перелистывание накапливало обработчики | Предыдущий `PageFlip` уничтожается перед заменой книги | 4 |
| P2 | PDF не перестраивался на телефоне | PDF получает новую раскладку и сохраняет текущую страницу | 4 |
| P2 | Нерабочая PDF-закладка вела на начало | Неразрешимые destinations исключаются | 4 |
| P2 | BAT не помогал после чистого клона | Первый запуск выполняет `npm ci`, затем запускает сайт | 5 |

## Проверенные сценарии

Команды, прошедшие на текущем ПК:

```powershell
npm run check
npm run test:formats
npm run test:reader
npm audit --omit=dev
git diff --check
```

`test:reader` проверяет ложное содержание, длинные абзацы/списки/таблицы, большой пользовательский DOCX, desktop/mobile, 99-страничный PDF, переходы, повторные импорты, фокус и `aria-expanded`. Он выбирает Brave, Edge или Chrome; путь можно задать переменной `TEXTBOOK_BROWSER_PATH`.

## Честные оставшиеся ограничения

| Приоритет | Ограничение | Почему это важно | Следующий этап исправления |
|---|---|---|---|
| P2 | Эвристика содержания не может безошибочно понять любой Word-файл с хаотичными стилями | Автор может применить стиль заголовка к библиографической строке или обычному абзацу | Добавить редактор оглавления: удалить ложный пункт, переименовать и назначить уровень/страницу вручную |
| P2 | Сложные формулы, OLE, SmartArt, плавающие объекты и крупные таблицы Word не гарантируют одинаковый вид | DOCX и Word HTML не являются форматом постраничной веб-вёрстки | Добавить предпросмотр импорта и набор эталонных файлов для сложных объектов; для точного вида советовать PDF |
| P2 | В PDF нет поиска и выделения текста | Сейчас PDF рисуется canvas для стабильного книжного вида | Добавить текстовый слой PDF.js и полнотекстовый поиск |
| P3 | Нет закладок, заметок, масштаба и сохранения позиции между запусками | Это полезно для длительного обучения, но не блокирует чтение | Добавить localStorage-профиль книги с хешем файла |
| P3 | Тесты с пользовательским DOCX/PDF не могут выполняться в чистом CI | Эти файлы намеренно не публикуются | В будущем добавить нейтральные открытые fixtures или CI-артефакты без персональных материалов |
| P3 | PPT/PPTX и XLS/XLSX не заявлены как поддерживаемые | Это другая семантика документа и другая модель чтения | Решить отдельно: режим слайдов/таблиц либо явная подсказка пользователю |
| P3 | Остатки Electron (`main.js`, `preload.js`, `dist/`, старые QA-файлы) сохранены на диске | Они не запускаются сайтом, но могут путать разработчика | Удалять только после отдельного подтверждения пользователя, чтобы не стереть нужные материалы |

## Порядок дальнейшей работы

1. Принять текущую веб-версию на реальных учебниках преподавателя.
2. Добавить ручное редактирование содержания — это даст наибольший эффект для нестандартных Word-файлов.
3. Добавить поиск, закладки и сохранение последней страницы.
4. Создать набор нейтральных тестовых документов и CI, затем решить вопрос об очистке наследия Electron отдельным согласованным изменением.
