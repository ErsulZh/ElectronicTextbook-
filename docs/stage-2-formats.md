# Этап 2 — единая модель документа и форматы

Статус: готов к независимой приёмке.

## Единая модель

Каждый непустой текстовый импорт теперь возвращает `DocumentModel` версии 1:

```text
{
  version, title, format,
  blocks: [{ type, level?, text, html }],
  assets, tocHints, notices, capabilities
}
```

Типы блоков: `heading`, `paragraph`, `list`, `table`, `image`, `code`. PDF возвращает такую же мета-модель с `format: "pdf"`; сами PDF-страницы загружаются диапазонами и отрисовываются отдельным PDF-читателем. Браузерная пагинация получает `document.blocks`, а не поле с произвольным HTML.

## Реальная поддержка

Одинаковая таблица опубликована на стартовой странице и в [README](../README.md). Её единственный машинный источник — `src/format-support.json`; сервер использует из него список разрешённых расширений, а браузер — список выбора файла и таблицу.

## Проверки

```powershell
npm run check
npm run test:formats
npm audit --omit=dev
```

`test:formats` создаёт временные валидные ODT и EPUB, а также проверяет Markdown, UTF-8/UTF-16LE/Windows-1251 TXT, безопасную обработку HTML, DocumentModel и отсутствие Microsoft Word. Тест не использует и не публикует пользовательские документы.

Дополнительно на текущем ПК вручную подтверждены импорт реального DOCX, DOC и PDF: у DOCX/DOC есть модель версии 1, PDF сохраняет модель и Range-ответ HTTP 206.

## Честные ограничения

- ODT и EPUB остаются в интерфейсе только как **ограниченно поддерживаемые**: формат не обещает таблицы, изображения, сложные стили или интерактивность.
- Устаревшие Word-форматы требуют найденный `WINWORD.EXE`; при его отсутствии сервер возвращает ясную подсказку, а макросы при конвертации отключены.
- Внешние ссылки, HTML-скрипты, стили и внешние ресурсы не переходят в DocumentModel.
