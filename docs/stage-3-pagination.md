# Этап 3 — содержание, страницы и мобильная книга

Статус: готов к независимой приёмке.

## Что исправлено

- Страница с напечатанным «Содержанием» не становится разделом. Темы начинают собираться только с первой фактической главы, заголовка или введения после неё.
- Сохраняются уровни `H1`–`H6`. Для типичных Word-документов без семантических заголовков распознаются нумерованные подразделы, главы, лекции и выделенные заголовки.
- Длинные абзацы делятся по словам и сохраняют внутреннюю разметку (`strong`, `em`, `code`, безопасные локальные ссылки). Маленький остаток присоединяется к предыдущему фрагменту, чтобы не появлялась страница с одним словом.
- Продолжения нумерованных списков получают корректный атрибут `start`; таблица повторяет шапку только если она действительно содержит `thead` или `th`. Первая строка простой таблицы не теряется.
- Страница не получает внутреннюю прокрутку: алгоритм измеряет высоту до вывода и переносит блоки. Для исключительного неразбиваемого элемента применяется уменьшение, а не обрезание нижней части за номером страницы.
- Заголовок раздела не остаётся один на листе: он удерживается со следующим подзаголовком или текстом.
- На телефоне содержание изначально скрыто и открывается кнопкой «Содержание»; при смене ширины книга перепагинируется.
- Для PDF приоритетны встроенные bookmarks. Печатное содержание разбирается только при наличии меток страниц PDF, поэтому программа не выдаёт ложные переходы при несовпадении физической и печатной нумерации. В остальных PDF остаётся честный переход на начало и поле номера страницы.

## Автоматическая приёмка

```powershell
npm run check
npm run test:reader
```

`test:reader` запускает локальный сервер и браузер без внешней сети, затем проверяет:

1. fixture с напечатанным содержанием: в TOC остаются только «Введение» и реальная тема, оба перехода работают;
2. fixture с длинным абзацем, разметкой, нумерованным списком и простой таблицей: нет переполнения, разметка, `start="7"` и первая строка таблицы сохранены; отдельно проверяется один список с 3 000 повторяющимися словами — он должен разложиться на листы менее чем за 30 секунд;
3. реальный пользовательский DOCX `Казакша электр аппараттары КІТАП 27.10.docx`: на десктопе 190 листов, без внутренней прокрутки, одиночных текстовых листов или листов только с заголовком; проверяются переходы в начале, середине и конце TOC, а библиографическая строка не попадает в TOC;
4. этот же документ при ширине 390 px: книга перепагинируется в 315 листов, не создаёт горизонтальную прокрутку, помещается на экран, а содержание скрыто до нажатия кнопки.

Тест не является обещанием идеального преобразования любой сложной таблицы, математической формулы или изображения из Word. Такие элементы требуют отдельного пользовательского образца и визуальной приёмки.

После автоматического теста выполнена ручная визуальная проверка: стартовый экран, импорт большого DOCX и переход к «4-ТАРАУ». Заголовок главы и подраздел `4.1` с текстом находятся на одном листе.
